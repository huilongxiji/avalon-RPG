# 规则管理后端 API

本项目已迁入完整规则管理后端及 `web/` 下的 Vue 页面。登录后可通过 `/items` 管理装备、`/formulas` 管理公式，
并通过 `/effects`、`/sets`、`/monsters`、`/dungeons`、`/drops`、`/props`、`/recipes`、`/prop-recipes`、`/stacks` 管理对应规则。
页面提供生效版本与草稿切换、编辑预检、差异对比、校验、激活和历史版本回滚；具体可用操作取决于账号角色。
本文说明这些页面使用的 API 行为。
规则代码位于 `servers/logic/src/avalon_logic/rules`；对外路由位于 `servers/api/src/avalon_api/routes/v1/rules_manage.py`。

## 规则管理行为

- 套装改名时，在同一草稿事务内同步更新装备的套装引用；激活后生效，回滚可恢复原关联。
- 效果预检返回参数代入后的中文描述和逻辑预览，预检不保存数据。
- 动作字段校验与引擎保持一致：`scale_hit` 支持 `base`、`at_least_1`；`replace_hit`、`reduce_hit` 不接受引擎未使用的这些字段。
- 默认礼盒配方也返回每份产出的 `quantity=1`，与已配置道具配方的响应结构保持一致。

上述行为不要求删除数据库或重新导入规则。部署后端代码后需重启后端；修改 Vue 源码后，部署环境需在 `web/` 重新执行 `npm run build`，产物由 API 从 `data/web/dist` 托管。

## 草稿流程

1. 使用网站账号登录，创建草稿：`POST /api/v1/edit/draft`。
2. 查询草稿中的类别记录与摘要；新建、修改前可调用对应 `/check` 预检接口。
3. 保存只修改草稿；传入草稿版本和原记录摘要，防止覆盖其他人的编辑。
4. `POST /api/v1/edit/draft/validate` 编译整个草稿并执行固定种子试战。
5. 管理员调用 `POST /api/v1/edit/draft/activate`，游戏随后读取新规则。
6. 需要恢复时调用 `POST /api/v1/edit/versions/{版本号}/rollback`。

编辑规则后的激活与回滚不要求重启后端。预检用于字段、引用和表达式检查，不执行完整试战；
完整校验也不等同于概率覆盖或数值平衡验收。

## API 对照

`category` 取值：`effects`、`sets`、`monsters`、`dungeons`、`drops`、`props`、`recipes`、`prop_recipes`、`stacks`。

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/catalog/manage/meta?draft=true` | 属性、引用、可用动作和时机、JSON Schema、新编号建议 |
| GET | `/api/v1/catalog/manage/{category}?draft=true` | 完整记录、版本、摘要、引用和删除限制 |
| POST | `/api/v1/edit/manage/{category}/check` | 新建预检，不保存；效果包含 `preview.description` 和 `preview.logic` |
| POST | `/api/v1/edit/manage/{category}/check?key={原代号}` | 修改预检，不保存 |
| POST | `/api/v1/edit/manage/{category}` | 新建草稿记录；掉落须先有怪物 |
| PUT | `/api/v1/edit/manage/{category}/{原代号}` | 修改记录 |
| DELETE | `/api/v1/edit/manage/{category}/{代号}` | 删除允许删除且没有引用的记录 |

新建请求为 `{"version_id": 13, "data": {...}}`。修改和修改预检额外提供 `before_hash`；
删除提供 `version_id` 和 `before_hash`。中文代号应做 URL 编码。省略 `draft` 或指定 `draft=false` 时读取生效版本。

内部对应 `/internal/rules/manage/...`，只接受内部令牌；它不直接对玩家或桌面模拟器开放。
装备、公式、设定及草稿生命周期仍使用原有 `/api/v1/edit/draft/...` 路由。

## 权限与数据保护

- 查看者可读取生效版本和草稿，编辑者可编辑草稿，管理员和超级管理员可激活与回滚。
- 查询需要网站会话，写操作还需要相应权限、同源检查和 CSRF；机器人、模拟器令牌不授予网站编辑权限。
- 草稿切换或记录摘要变化返回 HTTP 409。规则写操作与激活在当前单进程逻辑服务内串行执行。
- 效果、怪物代号及数字编号保存后固定；套装名称可修改并同步装备关联。其他按名称引用的规则改名须先解除引用。
- 被装备、套装、副本、配方、设定或表达式引用的记录不可直接删除；曾在生效或归档版本发布的道具保留历史编号。
- 掉落属于怪物，两个编辑入口共用冲突保护；可清空掉落列表，不能独立删除怪物的掉落记录。
- 无效字段、非法引用、表达式错误、非有限数值或未实现动作不会保存；规则与审计同事务写入。
- 装备配方使用背包装备/材料，道具配方使用道具仓库，配置中的每份产出数量参与实际合成发放。

网站账号配置见 [网站账号管理](网站账号管理.md)。

## 独立回归

`servers/api/tests/test_rules_management_http.py` 使用合成规则、四个内存数据库和真实 API → Logic 的 ASGI 链路，
覆盖权限、服务令牌隔离、CSRF、HTTP 409、中文键、效果预览、发布、回滚和审计，不连接外部服务或读取旧实例存档。
另外检查九类合成文档与代码内置复杂效果的编辑解析兼容性。这里不沿用旧实例全部规则或浏览器测试的验收数量。

在项目根目录运行：

```sh
uv run --project servers --locked pytest servers/api/tests/test_rules_management_http.py servers/logic/tests/store/test_rules_management.py -q
```
