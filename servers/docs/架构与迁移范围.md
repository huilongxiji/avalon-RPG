# 架构、目录与迁移范围

Avalon RPG 已整合 `avalon_gj` 的 API、逻辑服务、NoneBot、Vue 业务源码及完整项目数据。
根 `main.py` 管理进程，业务代码按 `servers`、`bot`、`web` 分离，SQL 集中于 `sql`，运行数据集中于 `data`。
自动公告插件与 `changelog` 目录保持移除；后端原公告接口和表结构为兼容保留。

## 调用关系

```text
QQ ↔ goqbot → 反向 WebSocket → NoneBot（7891）
                                   ↓ HTTP + bot 令牌 + 玩家身份
Vue（开发端口 5173）→ API（7900）→ Logic（7901）
                       ↓              ↓
                    data/api.db    data/rules.db · game.db · stats.db · sim/
```

NoneBot 和网站经 API 访问业务，API 承担鉴权、会话、审计与事件转发，Logic 承担游戏、规则与模拟计算。
网站账号、机器人令牌及模拟器令牌分别鉴权；NoneBot 不直接读取游戏数据库。
API、Logic、NoneBot 共用 `servers/contracts` 数据契约。

| 部分 | 路径 | 职责 |
| --- | --- | --- |
| 统一入口 | 根 `main.py`、`avalon.toml` | 环境选择、前端依赖安装、端口检查、就绪等待、退出清理 |
| 后端入口 | `servers/app.py` | 初始化配置、同步服务令牌、升级数据库，先 Logic 后 API |
| API | `servers/api` | 对外接口、鉴权、会话、审计、SSE 与 WebSocket |
| Logic | `servers/logic` | 角色、装备、道具、战斗、BOSS、市场、规则与模拟 |
| 共享契约 | `servers/contracts` | 请求响应、规则、错误与事件模型 |
| NoneBot | `bot/nonebot` | health、status、game、oops 四个插件及消息排版 |
| goqbot | `bot/goqbot` | 本机原生程序及配置，程序自行按系统与架构提供 |
| Vue | `web` | 网站完整业务源码、前端依赖清单及锁文件 |
| SQL | `sql` | SQL 脚本与模板；私密 SQL 保存在忽略提交的 `local` |
| 运行数据 | `data` | 数据库、模拟结果、日志、缓存、构建产物及备份 |

## 启动与环境

| 工作目录 | 命令 | 启动范围 |
| --- | --- | --- |
| 项目根 | `uv run main.py` | 后端 → NoneBot → goqbot → Vue |
| `servers` | `uv run app.py` | Logic 与 API |
| `bot/nonebot` | `uv run bot.py` | NoneBot |
| `web` | 首次 `npm ci`，然后 `npm run dev` | Vue 开发服务 |

根项目、后端、NoneBot 各有独立的 `pyproject.toml` 和 `uv.lock`。
后端 uv workspace 包含 `contracts`、`logic`、`api`；NoneBot 通过 `../../servers/contracts` 引用共享模型。
`uv run` 无需手动激活环境；若已激活其他 `.venv` 并出现 `VIRTUAL_ENV ... does not match`，先执行 `deactivate`。

统一入口在首次运行、前端依赖文件变化或 `web/node_modules` 缺失时执行 `npm ci`；
安装记录和 npm 缓存放在 `data/cache/npm`，安装失败时不启动服务。
Vue 默认绑定 `127.0.0.1:5173`，严格使用该端口，不自动递增；入口检查端口并等待 HTML 页面就绪。
Vite 开发代理从后端配置解析 API 地址，Vite 缓存位于 `data/cache/vite`。
在 `web` 执行 `npm run build` 生成 `data/web/dist`，API 可从默认 7900 端口托管静态页面。

goqbot 不使用 uv，也不另建启动脚本。默认文件名为 `goqbot`；Windows 可用 `goqbot.exe`，
或在 `avalon.toml` 中指定实际文件名。Unix 系统需要执行权限。
缺少 `bot/goqbot/config/config.yml` 时，首次统一启动只运行 goqbot 生成配置，
不启动其他服务、不检查旧服务端口。填写后再次启动整套服务。`--check` 不生成配置或安装前端依赖。

goqbot 日志、ID 映射及插件数据以可执行文件目录为基准，所以统一入口首次将程序复制到 `data/goqbot` 运行，
并显式传入 `-config` 指向 `bot/goqbot/config/config.yml`，后续保留运行副本及其自更新。
独立运行也应使用该运行副本与显式配置路径；直接在 `bot/goqbot` 中裸启动会在源码目录旁生成配置和数据库。
具体命令见 [goqbot 说明](../../bot/goqbot/README.md)。

Ctrl+C 或任何已启动服务失败时，入口清理本次启动的进程及子进程。
默认端口已被其他实例占用时会报错退出，不会接管或停止旧实例。

## 配置和数据

项目根由 `avalon.toml` 定位。后端读取 `servers/.env`；NoneBot 读取 `bot/nonebot/.env` 和选中的 `.env.dev` 或 `.env.prod`；
goqbot 配置固定为 `bot/goqbot/config/config.yml`。配置均保留在所属组件目录。

完整数据迁移保留 RPG 现有的后端与 NoneBot 连接配置。后端启动时按现有配置同步数据库中的服务令牌，
为 NoneBot 的空白 API 令牌和默认地址提供配置；已有非空令牌、自定义地址及管理员配置不覆盖。
goqbot 配置与 NoneBot 的 OneBot 令牌须对应。Vue 私有后端令牌不会暴露给浏览器。

| 数据 | 根目录下的位置 |
| --- | --- |
| 规则、玩家、统计、网站账号数据库 | `data/rules.db`、`data/game.db`、`data/stats.db`、`data/api.db` |
| 模拟任务库及任务结果 | `data/sim` |
| NoneBot 运行工作目录 | `data/nonebot` |
| goqbot 运行副本、ID 映射及日志 | `data/goqbot` |
| 原项目根日志 | `data/logs/legacy-avalon_gj` |
| 旧版原始数据 | `data/legacy/old_data` |
| 桌面模拟器场景数据 | `data/legacy/simulator/scenarios` |
| Python、npm、Vite 等缓存 | `data/cache` |
| 网站构建产物 | `data/web/dist` |
| 迁移前目标备份 | `data/backups/full-migration-20261125-031901.tar.gz` |

数据库及其 WAL、SHM、journal 等附属文件、`data` 内容、真实配置与可执行文件均不提交 Git。
`bot/goqbot` 在 Git 中仅保留 README，初始配置由原生程序生成，不提供项目模板。
两份私密 SQL 放入 `sql/local` 并忽略提交。`.venv` 和 `web/node_modules` 是工具依赖环境，源码资源与 SQL 属于项目文件。

## 完整迁移范围

本次迁入 Vue 全量业务源码，并以一致性快照迁移旧项目数据，不再沿用早期“只迁代码”或“只导入生效规则”的限制。
快照包含 526 个文件、37,402,007 字节，迁入后逐个文件哈希一致；四个业务 SQLite 数据库和模拟任务库均通过完整性与外键校验。
保留 39 名玩家、1 个网站账号、5 个模拟任务，以及全部 13 个规则版本和原始版本 ID；
规则生效版本仍为 12、草稿为 13。这覆盖上一阶段在 RPG 中单独导入的规则版本 1，原目标数据先备份。

| 源项目内容 | 目标位置 |
| --- | --- |
| 根 `data/` | 根 `data/`，保持相对路径 |
| 根 `logs/` | `data/logs/legacy-avalon_gj/` |
| goqbot 的 `idmap.db` 和日志 | `data/goqbot/` |
| `old_data/data/` | `data/legacy/old_data/` |
| `simulator/scenarios/` | `data/legacy/simulator/scenarios/` |
| 两份私密 SQL | `sql/local/` |

goqbot 的 `idmap.db` 为 bbolt 格式，随一致性快照迁移。迁移前目标数据、配置与占位 `web` 归档到
`data/backups/full-migration-20261125-031901.tar.gz`。源 `avalon_gj` 保持原样，便于核对与回退。
新的目录结构及根启动器承担运行职责，自动公告插件和 `changelog` 不随完整迁移恢复。

运行数据只保存在本机，新的 Git 检出仍可能没有规则库。空规则状态下世界 BOSS 结算会等待，
不写结算标记；导入并激活规则、重新加载规则快照后，下一轮自动恢复并保持结算幂等。
