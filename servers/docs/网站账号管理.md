# 网站登录与账号管理

Vue 网站已迁入 `web/`，提供 `/login` 登录页及 `/users` 网站用户管理页。下文管理的网站账号与游戏玩家、QQ 身份、机器人和模拟器令牌独立。
网站业务接口必须登录才能访问，本机访问也不能跳过登录；未登录访问管理页面会跳转到 `/login`。
没有注册页面、注册 API、新增账号按钮、自动创建管理员或创建账号命令。
账号只能由维护者手动执行 SQL 插入 `data/api.db` 的 `admin_users` 表。

本次完整数据迁移已原样保留旧项目的 1 个网站账号及其权限，不需要重新初始化或覆盖原账号，可沿用原登录凭据。

## 空库首次配置或新增账号

以下步骤仅用于新空库创建首个账号，或在已有数据库中新增账号。命令都在项目根目录执行，先用 `uv sync --project servers --locked` 安装依赖。
账号由维护者自行填写和入库；程序不会配置默认账号或密码。

1. 更新数据库结构（不会添加账号、不会修改游戏数据库）：

   ```bash
   uv run --project servers --locked avalon-api-migrate
   ```

2. 生成密码哈希，密码通过终端隐藏输入，不放在命令行或 SQL 中：

   ```bash
   uv run --project servers --locked python -m avalon_api.auth.passwords
   ```

   密码为 12～128 个字符。工具只输出哈希，不连接数据库，不创建账号。

3. 复制模板，填写用户名、上一步的完整哈希和角色：

   如已有同名本机 SQL 文件，请先换用新文件名，避免覆盖已有记录。

   ```bash
   mkdir -p sql/local
   cp sql/website-user.sql.example sql/local/website-user.local.sql
   ```

   只修改模板中 `VALUES ('', '', 'super');` 这一行：第一个空字符串填用户名，第二个填完整密码哈希，第三个填角色。
   不要修改上面的 `CHECK` 约束。首个账号角色使用 `super`，新增账号按实际需要选择下表角色。用户名区分大小写，不能带首尾空格；SQL 字符串内的 `'` 要写成 `''`。
   `sql/local/` 已被 Git 忽略。模板未填写时会拒绝插入；重复用户名会报错，不会覆盖已有账号。

4. 手动执行 SQL：

   ```bash
   sqlite3 -bail data/api.db < sql/local/website-user.local.sql
   ```

5. 单纯通过 SQL 添加账号后不需要重启。网站运行后打开 `/login`，使用填写的账号登录。
   开发环境默认地址为 `http://127.0.0.1:5173/login`；使用 API 托管构建产物时，默认地址为 `http://127.0.0.1:7900/login`，实际端口以配置为准。
   网站通过 `/api/v1/auth/login` 建立会话，并处理 `X-Avalon-Client: web`、同源请求与 CSRF 校验。

Vue 开发服务在 `web/` 执行 `npm run dev`，根目录 `uv run main.py` 也会启动它。
部署时在 `web/` 执行 `npm run build`，产物写入根 `data/web/dist`，由 API 托管。
首次构建完成后需启动或重启 API，才能挂载网站目录；更新后端代码时也需重启后端。独立后端入口为 `servers/` 下的 `uv run app.py`，整套项目入口为根目录的 `uv run main.py`。

## 权限

| 角色 | 网站查看 | 编辑、校验规则草稿 | 激活、回滚规则 | 管理网站账号 |
| --- | --- | --- | --- | --- |
| viewer（访客） | 是 | 否 | 否 | 否 |
| editor（编辑者） | 是 | 是 | 否 | 否 |
| admin（管理员） | 是 | 是 | 是 | 否 |
| super（超级管理员） | 是 | 是 | 是 | 是 |

超级管理员可进入 `/users` 页面查询现有账号、调整角色、启用或禁用账号、重置他人密码；其他角色不能进入该页面或调用账号管理接口。
所有已登录用户都可以通过页面右上角修改自己的密码和退出登录。不能禁用自己、降低自己的权限，必须保留可用的超级管理员。
不提供账号删除，停用使用“禁用”，保留历史审计关联。

禁用、修改角色或修改密码会撤销该账号的所有网站会话。重新启用也不会恢复旧会话。
直接用 SQL 修改密码、角色或用户名同样会使旧会话失效；手动禁用时也建议在同一事务内删除对应
`web_sessions`（`WHERE user_id = ...`），避免手动重新启用后恢复未过期会话。
数据库操作不受网页的“保留超级管理员”保护，维护者自行确保至少有一个可用 `super`。

## 会话与部署

- 密码采用随机盐的 PBKDF2-HMAC-SHA256，600,000 次迭代；数据库只保存密码哈希。
- 会话有效期 8 小时；令牌放在 HttpOnly、SameSite=Lax Cookie，数据库只保存令牌哈希。
- 修改请求校验会话 CSRF 令牌和浏览器来源；后端不要求把会话或密码保存在浏览器 localStorage。
- 登录按用户名和连接 IP 限流。当前单进程 API 内存窗口为 15 分钟，用户名 10 次、IP 60 次；
  成功登录清除用户名桶。重启会清空窗口；若以后使用多进程或多实例，需改为共享限流存储。
- 网站 API 不缓存业务响应；登录、退出、账号变更和密码变更记录到 `audit_log`，不记录密码、哈希或令牌。
- 本机 HTTP 开发模式可直接运行。对外部署使用 HTTPS，并设置 `AVALON_WEB_COOKIE_SECURE=true`。
  反向代理必须保留外部 `Host`，否则来源校验会拒绝请求；不要对账号接口开启跨站 CORS。
- 机器人与模拟器仍使用 Bearer 令牌。系统健康摘要兼容这两类服务令牌，网站管理接口不接受它们。

密码和会话实现参考 [OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
及 [CSRF 防护建议](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。
